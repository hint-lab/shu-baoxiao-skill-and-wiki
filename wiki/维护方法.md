# 维护方法

## 一份知识源

`skills/shu-reimbursement/references/knowledge/documents.jsonl` 是资料源。每条记录包括官方 URL、原文、网页标注日期、资料获取时间、附件入口、正文可用状态和生效核验状态。页面日期不一定反映附件版本，不能互相代替。

场景分类和追问点保存在 `references/scenarios.json`。它们只是帮助查资料，不是校方强制材料规则。初版不沿用旧应用的启发式“必须材料”清单。

[材料整理总览](材料整理.md)、[类型目录](资料目录.md)、[表格入口](空白表格.md)、[缺口清单](待补资料.md) 和 [重复入口核对](重复入口.md) 均由同一份资料生成；新增或补全文字后重新构建即可更新。主题标签和资料类型属于辅助分类，不能替代适用条件或生效日期判断。

## 补充或更新

```bash
python3 tools/maintain.py refresh https://cwc.shu.edu.cn/info/1113/4276.htm
```

脚本只访问公开学校来源，不登录、不绕过验证码。它更新网页快照并记录附件入口；PDF、图片、压缩包和表格仍需人工取得、核对和提取。取得可读文字后：

```bash
python3 tools/maintain.py import-text --url '<官方URL>' --title '<标题>' --text '<UTF-8文字文件>'
```

附件导入只是“取得可读正文”，不自动证明当前有效。涉及限额、身份差别、经费类型或制度替代关系时，阅读后续文件再核对；有疑问时保留待确认。

扫描件导入命令需增加 `--ocr`，并在文字中保留 PDF 页码；这样会标记 `text_quality=ocr_unverified`。若取得原文件，也应记录其校验值及获取方式。OCR 仅用于检索和定位；数字、表格和否定条件必须查看原件。含个人姓名、学号、银行卡号等示例的页面需先删节，不能将原图或未经处理的文字发布到公共仓库。[机器识别待核对资料](待核对资料.md) 集中列出需复核的扫描件。

## 发布前

```bash
python3 tools/build.py
python3 -m unittest discover -s tests -v
python3 tools/build.py --check
```

检查 Git 差异，核对变更的来源、适用条件与状态。发布新版本时修改 `SKILL.md` 的 `metadata.version`；构建会统一写入资料清单和 WorkBuddy 包。Wiki 的原文阅读页、资料目录以及技能内的参考资料自动同步，不手工各改一份。构建产生 Codex ZIP、WorkBuddy ZIP 和普通聊天场景包；GitHub Actions 也会生成这些文件供下载。

代码和资料验证、客户端实际安装、报销业务认可是不同状态。未做过的验证不要写成已通过。GitHub 仓库更新不会自动传到大家的电脑，使用者需要取得新版本并替换原有技能包。

## 共建

纠错请附官方来源、原文段落、涉及的业务日期和适用条件。退回经历可以作为去核对规则的线索；单个案例不能直接改成所有人的必需条件。不得附真实姓名、账号、票据、签字、登录状态或其他私人材料。

初始迁移保留了旧应用的 Git 历史和独立本地备份，未将真实个人业务数据迁入新知识库。
