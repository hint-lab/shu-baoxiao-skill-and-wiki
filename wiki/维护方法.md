# 维护方法

## 一份知识源

`skills/shu-baoxiao/references/knowledge/documents.jsonl` 是资料源。每条记录包括官方 URL、原文、网页标注日期、资料获取时间、附件入口、正文可用状态和生效核验状态。页面日期不一定反映附件版本，不能互相代替。

场景分类和追问点保存在 `references/scenarios.json`。它们只是帮助查资料，不是校方强制材料规则。初版不沿用旧应用的启发式“必须材料”清单。

[材料整理总览](材料整理.md)、[类型目录](资料目录.md)、[表格入口](空白表格.md)、[缺口清单](待补资料.md) 和 [重复入口核对](重复入口.md) 均由同一份资料生成；新增或补全文字后重新构建即可更新。主题标签和资料类型属于辅助分类，不能替代适用条件或生效日期判断。

## 补充或更新

```bash
python3 tools/maintain.py refresh https://cwc.shu.edu.cn/info/1113/4276.htm
```

脚本只访问公开学校来源，不登录、不绕过验证码。它更新网页快照并记录附件入口；PDF、图片、压缩包和表格仍需人工取得、核对和提取。取得可读文字后：

```bash
python3 tools/maintain.py import-text --url '<官方URL>' --title '<标题>' --text '<UTF-8文字文件>'
```

附件导入只是“取得可读正文”，不自动证明当前有效。涉及限额、身份差别、经费类型或制度替代关系时，阅读后续文件再核对；有疑问时保留待确认。

Word 可用 `skills/shu-baoxiao/scripts/word_to_markdown.py` 提取结构；PDF 可使用经授权的 P330 MinerU 服务和 `tools/mineru_markdown.py`。导入这些解析结果时使用 `--format markdown`；扫描件还需加 `--ocr`。导入前核对图片、脚注、表格和个人信息，程序会拒绝不安全的 HTML 与图片链接。

学校正文有时嵌在 PDF 或逐页图片中，网页只有标题并不代表没有正文。经逐页检查可公开的文件，可以记录 `original_page_images`：每页保存独立图片路径、页码及 SHA-256，构建时在对应识别文本上方显示；完整原始 PDF 副本应单独记录来源与哈希。页图不能用于尚未处理的个人信息页面。来自其他学校官方页面的同标题、同文号文件要标出实际来源，不得声称与无法下载的附件字节一致。

涉及操作截图的手册可使用 `tools/sanitize_manual.py`，结合原 PDF 的 `pdftohtml` 页面布局和 MinerU 页码剔除截图及重叠文本；这只是隐私筛查辅助，不能证明没有遗漏。完成逐页人工核查前标为 `partial_text`，写清哪些截图或文字未公开。原生文字层补充与识别内容可能重复，不得当作独立证据。视频的画面摘要也不是完整转写。

扫描件导入命令需增加 `--ocr`，并在文字中保留 PDF 页码；这样会标记 `text_quality=ocr_unverified`。若取得原文件，也应记录其校验值及获取方式。OCR 仅用于检索和定位；数字、表格和否定条件必须查看原件。含个人姓名、学号、银行卡号等示例的页面需先删节，不能将原图或未经处理的文字发布到公共仓库。[机器识别待核对资料](待核对资料.md) 集中列出需复核的扫描件。

## 发布前

用户明确要求记录的学院执行口径保存在 `skills/shu-baoxiao/references/knowledge/reported-practices.json`，不混入官方原文资料源。保留用户原话、记录日期、学院、物品和经费范围，以及未取得书面依据、与现有条文的差异；检索及相关清单单独显示。可用 `knowledge.py practice 计算机学院 --json` 读取，补充书面依据前不得标为已核验校规，也不能由用户口径推导采购或资产管理豁免。

常用材料清单维护在 `skills/shu-baoxiao/references/knowledge/checklists.json`，从已阅读的官方原文形成版本摘要，记录适用条件、材料项、原文位置、核对日期和正文校验值。新增、纠错或到复核日期时，对照原件复核相关条款后再更新摘要、日期与校验值；不得只刷新元数据来消除失效提示。30天提醒为项目复核策略，不是学校规定或规则有效期。未覆盖的条件继续查原文，个人事项的状态和真实材料不写入共享清单。

可用 `python3 skills/shu-baoxiao/scripts/knowledge.py checklist --json` 查看分支，或用 `checklist printer --json` 查看打印机清单及来源状态。来源正文变化、缺失或到复核日期时，工具停止输出可直接套用的材料项，提示先复核。发现新文件或冲突时，可先把对应 `source_reviews` 的 `status` 置为 `needs_review` 暂停复用；复核后改回 `reviewed`。人读清单页与 Wiki 入口统一由构建生成，不另行手改。

```bash
python3 tools/build.py
python3 -m unittest discover -s tests -v
python3 tools/build.py --check
```

检查 Git 差异，核对变更的来源、适用条件与状态。发布新版本时修改 `SKILL.md` 的 `metadata.version`；构建会统一写入资料清单和 WorkBuddy 包。Wiki 的原文阅读页、资料目录以及技能内的参考资料自动同步，不手工各改一份。构建产生 Codex ZIP、WorkBuddy ZIP 和普通聊天场景包；GitHub Actions 也会生成这些文件供下载。

代码和资料验证、客户端实际安装、报销业务认可是不同状态。未做过的验证不要写成已通过。GitHub 仓库更新不会自动传到大家的电脑，使用者需要取得新版本并替换原有技能包。

## 共建

统一反馈入口为 [GitHub Issues](https://github.com/hint-lab/shu-baoxiao-skill-and-wiki/issues/new/choose)，说明见[反馈与纠错](反馈与纠错.md)。维护者可在Issue中记录待核实、需补充、已核实、已修正或不适用的处理状态；不要将“已提交反馈”写成“已经采纳或发布”。

先核学院、经费、业务日期和适用版本。有公开书面依据的修正规则与清单；用户提供的实际执行口径另行记录来源、范围及书面差异。未经核实的退回或成功案例不自动变成通用规则。修正发布后再说明对应版本，使用者仍需更新已安装的包。

纠错请附官方来源、原文段落、涉及的业务日期和适用条件。退回经历可以作为去核对规则的线索；单个案例不能直接改成所有人的必需条件。不得附真实姓名、账号、票据、签字、登录状态或其他私人材料。

初始迁移保留了旧应用的 Git 历史和独立本地备份，未将真实个人业务数据迁入新知识库。
